# 背书工具 PRD

## 1. 文档信息与目标

- 产品名称：背书工具。
- 目标平台：本机桌面浏览器，主要适配 1920×1080；窄窗口允许滚动。
- 应用目录：`applications/背书工具/`。
- 项目根目录：`outputs/背书工具/`，每个项目独占一个子目录。
- 目标：用户粘贴纯文本后，应用自动调用 Codex 和 `mark-memory-spans` 提取记忆要点；用户可调整要点并保存，再按难度与隐藏比例练习背诵。
- 本阶段为单机使用，不需要账号、云同步或多人协作。

## 2. 与背图工具的差异

- 沿用 `applications/背图工具/` 的三栏布局、编辑/练习模式、项目列表、属性面板、本地服务、显式状态机和项目保存体验。
- 中栏主体改为保留段落与换行的逐字文本视图；不使用图片画布、矩形几何编辑或图片资源。
- 新建项目输入为粘贴的纯文本。提取由本地服务组织 skill 状态机与 Codex 语义选择；文本区间、校验、保存和抽样由脚本完成。
- 项目文件保存原文、记忆要点方案及来源信息。用户再次打开项目时直接加载已保存方案，不重复调用 Codex。

## 3. 用户流程

### 3.1 新建与打开

1. 用户在左栏点击“新建项目”，输入标题并粘贴非空纯文本。
2. 应用规范化换行，显示文本预览，提交给本地服务。服务启动 `mark-memory-spans` 状态机，将候选包交给 Codex 判断，再调用 skill 验证并读取结果。
3. 每个提取出的连续区间成为一个记忆要点；应用显示提取结果，默认进入编辑模式。提取失败时保留原文与可手工编辑的空方案，并显示可重试入口。
4. 用户点击“保存”，应用创建项目目录并保存 `source.txt` 和 `project.json`。尚未保存时切换项目须提示保存、放弃或取消。
5. 从左栏选择项目时，读取项目目录中的文件，校验原文哈希及各区间，恢复编辑方案；练习显隐状态重新初始化。

### 3.2 编辑

1. 原文固定，编辑模式仅允许增删和修改记忆要点及其属性。
2. 右键点击一个字：未标记时为它新建记忆要点；已标记时从所属记忆要点移除。只在编辑器内阻止浏览器右键菜单。
3. 按住右键从“北”拖到相邻的“京”，默认创建一个包含“北京”的记忆要点；从已标记字开始拖动则批量移除经过文字的记忆要点身份。单次拖动采用起点决定的统一操作，不因经过不同字而反复切换。
4. 左键点击文字或其背景圆形，选中该字所属的记忆要点并在右栏修改属性。
5. 右栏允许把所选字或所选连续区间归入已有记忆要点。因此同一个记忆要点可含不相邻的区间，例如“北京……首都”中的“北京”和“首都”；点击其中任一部分时，整个记忆要点联动显隐。
6. 删除某个区间后，剩余区间继续属于原记忆要点；最后一个区间被删除时，删除该记忆要点。区间不得重叠，同一字最多属于一个记忆要点。
7. 每个记忆要点只有一种背景颜色；自动提取及手工新增要点时尽量分配不同颜色，手动改色允许重复。在右栏修改任一成员字的圆形颜色时，整个记忆要点的圆形及练习占位颜色同步更新。
8. 编辑器中相邻文字保留适度水平与行间距，以清楚显示背景圆形；保留原文段落和换行。普通空格作为间距，换行不生成圆形。
9. “保存”及 Ctrl+S 将方案写入本地项目文件；未保存修改可撤销/重做，Ctrl+Z、Ctrl+Y 可用。

### 3.3 练习

1. 练习工具栏显示“显示所有答案”“隐藏所有答案”、难度下拉框、隐藏比例滑动条及同步数字输入框、开始练习按钮。
2. 难度为简单（默认）、中等、困难；隐藏比例限制为 0% 至 100%。滑动条与数字输入框双向同步，越界输入按边界值修正。
3. 点击“开始练习”时，以记忆要点数量为基数，随机选取约 `round(要点总数 × 隐藏比例 / 100)` 个要点隐藏；每次重新开始重新抽取。同一要点的全部区间同时隐藏。
4. 点击隐藏部分的任一圆形或占位形状，显示该要点所有区间的原文；再次点击则重新隐藏。显示所有答案、隐藏所有答案立即作用于全部要点，不改变保存的方案。
5. 简单：仅隐藏要点文字，每个字符背后的圆形保持编辑时的填充颜色和透明度。中等：每段隐藏区间显示有填充、无描边、宽度随该段字符数增长的矩形。困难：每段显示有填充、无描边、宽度与实际字符数无关的随机矩形；宽度在一次练习中保持稳定。
6. 练习中的抽样、随机宽度、显隐状态与当前难度不写入项目文件。返回编辑模式或重新打开项目后，不沿用临时状态。

## 4. 界面布局与属性

- 左栏：新建项目、项目列表、项目切换、重命名、确认删除及最右侧拖拽柄排序。重命名修改项目标题但不改目录名；删除项目同时删除本地项目文件。顺序跨应用重启保持稳定。沿用背图工具的视觉语言和主要间距。
- 中栏上方：项目标题、编辑/练习切换、保存状态及对应模式的工具栏；下方为可滚动的纯文本主体。
- 右栏：未选中时显示项目与原文摘要；选中字时显示所属记忆要点 ID、所选文字、包含的区间、背景颜色、加入已有要点及移除操作。加入已有要点后，颜色采用目标要点的颜色。
- 要点 ID 显示为“要点 ID：”加 UUID 前 8 位；“选择目标要点”包含当前分组，重复选择当前归属不形成新编辑。自动提取使用共享术语表，术语不会从中间切成记忆要点。
- 编辑模式保留文字可读性，背景圆形显示在文字后方；练习模式中仅隐藏被抽中的要点文字，原文其他部分保持原样。
- 对键盘操作提供可见焦点和可访问名称；鼠标右键拖动之外提供右栏按钮完成同样的加入、移除与颜色修改。

## 5. 状态机与职责

- 应用流程使用显式状态：`recent_projects → creating_project → extracting_spans → reviewing_extraction → editor_editing ↔ editor_practice`；保存经过 `saving` 后回到编辑或练习状态，读取经过 `opening_project`，冲突和失败进入相应可恢复状态。
- 提取流程由本地 Python 服务组织：`prepared → validating_text → skill_start → awaiting_codex_selection → skill_resume → verifying_result → imported`。失败进入 `failed`，前端回到编辑状态，保留原文并允许重试或手工编辑。
- `mark-memory-spans` 现有 skill 负责候选、语义输出验证、原文哈希、区间校验及产物。Codex 只填写该 skill 所需的少量结构化语义判断；不得由前端直接拼接或信任未经验证的区间。
- 初次提取与项目编辑分开：skill 输出采用连续、不重叠区间；应用允许用户后来把多个不连续区间归入同一记忆要点。保存前由共享校验脚本检查区间边界、互不重叠、原文哈希和颜色格式。
- 保存服务校验项目修订号并原子写入；发现磁盘版本变化时阻止静默覆盖，并提供保留当前草稿或重新打开的选择。

## 6. 项目目录与 JSON schema/template

采用 `outputs/背书工具/<清理后的标题>_<YYYYMMDDTHHMMSS>/`；同名且时间戳完全相同时依次追加 `_1`、`_2`。时间戳只通过 `utils/scripts/timestamp.py` 生成。

```text
<项目目录>/
├── project.json
└── source.txt
```

`source.txt` 保存统一为 LF 换行的 UTF-8 原文。`project.json` 使用以下模板；其中 `segments` 是零基、左闭右开的 Python 字符位置，允许同一记忆要点有多个不相邻区间，所有记忆要点的区间整体不重叠。模板中的尖括号值表示运行时生成的数据。

工作区根目录另存 `project-order.json`，采用已确认的 `{"schemaVersion":1,"projectIds":["<项目 UUID>","..."]}`；仅保存项目顺序，不改变单个项目的 schema。新项目加入列表，已删除项目从顺序中移除。

```json
{
  "schemaVersion": 1,
  "projectId": "<uuid>",
  "title": "北京是中国首都",
  "directoryName": "<目录名>",
  "revision": 1,
  "lastWriterId": "<uuid>",
  "createdAt": "<由 timestamp.py 生成>",
  "updatedAt": "<由 timestamp.py 生成>",
  "lastOpenedAt": "<由 timestamp.py 生成>",
  "source": {
    "path": "source.txt",
    "sha256": "<64 位 SHA-256>"
  },
  "extraction": {
    "source": "mark-memory-spans",
    "runId": "<skill run id>",
    "status": "verified"
  },
  "memorySpans": [
    {
      "id": "<uuid>",
      "segments": [
        {
          "start": 0,
          "end": 2
        },
        {
          "start": 5,
          "end": 7
        }
      ],
      "color": "#5B8DEF",
      "role": "记忆要点"
    }
  ]
}
```

- `source.sha256` 是规范化后 `source.txt` 的 UTF-8 SHA-256；读取时重新计算，失败则拒绝加载并报告。
- `memorySpans[].segments` 按起点升序保存，单个区间须非空且落在原文范围内；每个记忆要点至少有一个区间。
- `memorySpans[].color` 应为六位十六进制颜色；字、圆形和矩形共用这一属性。
- `extraction` 仅记录来源及可追溯的 skill run ID；用户手工添加的要点不需要伪造 skill 来源。
- 项目 JSON 不保存练习抽样、显隐状态、随机宽度、选中字、撤销历史或视图滚动位置。
- 新版本 schema 必须提供迁移或明确拒绝并说明原因，不静默丢弃字段。

## 7. 实现约束

- 前端优先沿用背图工具的 React、Vite、TypeScript 技术栈；本地服务及可固化逻辑优先用 Python。
- Codex 调用只能由本地服务发起；提取进度、失败原因及重试状态回传前端。服务必须使用现有 skill 的 `start → resume → verify` 契约，不绕开状态机。
- 索引统一使用 Python 字符位置。前端在字符渲染及选取时显式建立浏览器文本位置到该索引的映射，避免 UTF-16 索引造成错位；组合字符不得被拆成不可显示的半个字。
- 本地项目内容保存在 `outputs/背书工具/`。skill 运行日志和状态保存在 `logs/mark-memory-spans/runs/<run-id>/`；应用启动与服务日志保存在 `logs/背书工具/runs/<run-id>/`。运行产物不得写入 `runtime/`。
- 标题、文本、项目 JSON 和路径均须校验长度、编码与目录边界；项目文件写入采用修订校验及原子替换。
- 应用交付包含 README、启动方式、项目 schema 校验、状态机实现和应用审计契约。

## 8. 验收标准

- 粘贴纯文本可新建项目，自动调用 Codex 与 skill；提取后的每个区间准确对应原文，失败可重试或手工完成。
- 右键单击可新增/移除记忆要点；右键从“北”拖至“京”只生成一个包含“北京”的要点；非相邻区间可在属性中归入同一要点。
- 一个要点内所有背景圆形共享颜色；左键点击字和点击其圆形具有相同选择行为。
- 练习模式的难度、比例同步、随机隐藏、点击整组显隐及显示/隐藏全部按钮符合第 3.3 节。
- 左栏各有效项目均可重命名、确认删除和从最右侧拖动排序；重启后顺序保持一致。
- 保存后关闭并重新打开项目，原文、区间归组、颜色及标题一致；练习临时状态不残留。
- 对无效 JSON、哈希不符、重叠或越界区间、修订冲突给出明确错误，不覆盖有效项目。
- 构建和类型检查通过；在 1920×1080 桌面浏览器完成核心交互验收。

## 9. 已确认的细节

- 右键拖动新增时，路径中已经属于其他要点的字默认跳过，以免误改已有分组；从已标记字开始拖动时，对经过的已标记字执行移除。
- 难度中的矩形宽度以每个隐藏区间为单位；一个要点有多个不相邻区间时分别画占位形状，但点击任一形状会联动整个要点。
- 英文、数字、标点作为可见字符参加圆形/矩形占位；空格保留间距，换行保留断行。
